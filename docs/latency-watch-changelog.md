# LatencyWatch 更新日志

## v1.1.0 (2024-XX-XX) - 新增用户等待时间统计

### ✨ 新增功能

#### 1. 用户等待时间指标（⭐ 核心更新）

**定义**：从 ASR 最后一帧（用户说完话）到 TTS 第一帧发送给终端（用户听到回复）之间的时间。

**计算公式**：
```
用户等待时间 = TTS 第一帧发送时间 - ASR 结束时间
```

**重要性**：
- ⭐ **这是最重要的用户体验指标**
- 直接反映用户对系统响应速度的感知
- 包含了 LLM 推理、TTS 准备、网络传输等所有中间环节

**正常范围**：
- ✅ 优秀：< 2.0s
- ✅ 良好：2.0-4.0s
- ⚠️ 一般：4.0-6.0s
- ❌ 较差：> 6.0s

**警告阈值**：> 4.0s 时触发性能优化建议

```python
def mark_tts_start(self):
    """标记 TTS 开始（第一帧音频发送给终端）"""
    self._tts_start_time = time.time()
    self.timestamps['tts_start'] = self._tts_start_time
    
    # 计算用户等待时间：从 ASR 结束到 TTS 第一帧发送
    if self._asr_end_time:
        user_wait_time = self._tts_start_time - self._asr_end_time
        self.timings['user_wait_time'] = user_wait_time
        logger.bind(tag=TAG).info(
            f"[LatencyWatch] Session {self.session_id[:8]}... - 用户等待时间: {user_wait_time:.3f}s"
        )
    
    logger.bind(tag=TAG).debug(f"[LatencyWatch] Session {self.session_id[:8]}... - TTS 开始（第一帧发送）")
```

### 💡 优化建议

#### 用户等待时间过长（> 4.0s）

用户等待时间 = LLM 推理时间 + TTS 准备时间 + 网络延迟

**优化方案**：

1. **使用流式 LLM 输出**
   - 边生成边发送，减少首字延迟
   - 配置支持 streaming 的 LLM 服务

2. **选择更快的 LLM 模型**
   - 阿里云百炼：qwen-flash > qwen-turbo > qwen-plus > qwen-max
   - 智谱 AI：glm-4-flash > glm-4-air > glm-4

3. **优化 Prompt**
   - 减少上下文长度
   - 精简 system prompt
   - 避免过长的对话历史

4. **使用流式 TTS**
   - 阿里云流式 TTS（AliyunStreamTTS）
   - 火山引擎双向流式 TTS（HuoshanDoubleStreamTTS）
   - 第一帧音频立即发送，无需等待全部合成

5. **降低 max_tokens**
   - 限制 LLM 最大生成长度
   - 默认 500 tokens，可适当降低到 300-400

6. **网络优化**
   - 选择就近的云服务区域
   - 使用 CDN 加速
   - 优化服务器带宽

### 🎯 使用场景

#### 场景 1：日常对话

- **目标**：用户等待时间 < 3.0s
- **配置**：
  - LLM: qwen-flash
  - TTS: AliyunStreamTTS (PCM 格式)
  - max_tokens: 300

#### 场景 2：复杂任务

- **目标**：用户等待时间 < 5.0s
- **配置**：
  - LLM: qwen-plus（更强的推理能力）
  - TTS: AliyunStreamTTS
  - max_tokens: 500

#### 场景 3：实时交互

- **目标**：用户等待时间 < 2.0s
- **配置**：
  - LLM: qwen-turbo（最快响应）
  - TTS: 本地 TTS（如 PaddleSpeech）
  - max_tokens: 200
  - 启用流式输出

### 📝 注意事项

1. **用户等待时间是核心指标**
   - 比单独的 LLM 或 TTS 耗时更重要
   - 直接决定用户体验好坏

2. **流式输出是关键**
   - 非流式：必须等待全部内容生成完才能播放
   - 流式：第一个字生成后立即播放，大幅降低等待时间

3. **网络延迟影响**
   - 云端服务受网络质量影响较大
   - 建议在相同地域部署服务器和云服务

4. **多次测量取平均**
   - 单次测量可能有波动
   - 建议观察多次对话的平均值
